# Чеклист документации

## Факты

- [ ] Purpose и audience определены.
- [ ] Фактический code/config прочитан.
- [ ] Commands проверены.
- [ ] Versions и paths актуальны.
- [ ] Неподтверждённые сведения отмечены.
- [ ] Project-specific правило не выдано за корпоративное.

## Структура

- [ ] Назначение находится в начале.
- [ ] Reader понимает prerequisites.
- [ ] Шаги расположены в безопасном порядке.
- [ ] Expected result указан.
- [ ] Validation и troubleshooting присутствуют по необходимости.
- [ ] Длинный документ имеет понятную навигацию.

## Примеры

- [ ] Пример минимален и выполняем.
- [ ] В примере нет secrets/client data.
- [ ] Code block имеет подходящий язык.
- [ ] Placeholder нельзя спутать с реальным credential.
- [ ] Output соответствует текущей version.

## Связность

- [ ] Canonical file выбран правильно.
- [ ] Relative links существуют.
- [ ] Термины используются одинаково.
- [ ] Нет ненужного дублирования.
- [ ] Устаревший текст в затронутом scope удалён.

## Handoff

- [ ] Owner понятен.
- [ ] Update trigger указан.
- [ ] Missing Sources перечислены.
- [ ] Документ готов к кросс-ревью.
