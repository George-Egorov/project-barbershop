# Использование Highbase Documentation

## Позитивные запросы

- «Используй `$highbase-documentation`, чтобы обновить README после изменения setup».
- «Опиши public contract компонента и его states».
- «Подготовь инструкцию для локального запуска проекта».
- «Зафиксируй принятое архитектурное решение».
- «Сделай onboarding-раздел для нового Frontend-разработчика».

## Выбор места

Перед созданием файла:

1. найти существующий canonical document;
2. проверить links из root README и `AGENTS.md`;
3. определить owner;
4. обновить существующий файл, если тема уже принадлежит ему;
5. новый файл создавать только для отдельной устойчивой темы.

## Источники фактов

Приоритет:

1. фактический code/config;
2. проверенные commands и tests;
3. `hb-development-standarts`;
4. project `AGENTS.md`;
5. утверждённая design/spec;
6. подтверждение owner.

AI output и внешняя статья не являются первичным источником проектного факта.

## Формат результата

    Создано/обновлено:
    - path — назначение.

    Проверенные источники:
    - file/config/standard.

    Validation:
    - command/link/example — result.

    Missing Sources:
    - неподтверждённые сведения.

    Следующее review:
    - owner или условие обновления.
