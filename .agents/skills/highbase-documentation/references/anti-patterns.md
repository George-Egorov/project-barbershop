# Антипаттерны документации

## Недостоверность

- Писать command без запуска или проверки config.
- Описывать planned behavior как реализованное.
- Выдумывать owner, SLA, API или directory.
- Скрывать missing source.
- Использовать устаревшую память модели вместо repository.

## Структура

- Создавать второй README для той же темы.
- Копировать полный corporate standard в project doc.
- Начинать с теории, не объяснив действие.
- Делать список терминов без рабочего сценария.
- Прятать critical warning в конце.

## Примеры

- Публиковать `.env` или реальный endpoint/token.
- Использовать client data в sample.
- Давать destructive command без backup/approval.
- Показывать пример, не соответствующий текущей version.
- Копировать большой generated output.

## Поддержка

- Создавать документ без owner/update trigger.
- Оставлять две противоречащие инструкции.
- Менять `spec.md` без просьбы.
- Редактировать generated docs вручную.
- Создавать auxiliary README/CHANGELOG внутри Skill.

## Язык

- Использовать vague «настроить как обычно».
- Смешивать разные термины для одной сущности.
- Заменять точный path словом «там».
- Писать обязательное правило как необязательный совет.
- Маскировать uncertainty уверенным тоном.
